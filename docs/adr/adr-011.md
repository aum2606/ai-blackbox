# ADR-011 — Pythia-70m-deduped with PyTorch hooks for Phase 3 capture

**Status:** Accepted for Phase 3.
**Context:** Phase 3 needs a real model to capture activations from (ADD §7.1, ADR-006). The machine has 15 GB RAM (little free at times) and an 8 GB GPU, and the platform must work CPU-first at no cost (ADR-008). ADR-010 deferred token IDs and measurements until a producer exists; this model is that producer.
**Decision:**
- Model: `EleutherAI/pythia-70m-deduped`, commit `e93a9faa9c77e5d09219f6c868bfc7a1bd65593c`, `model.safetensors` only, float32, CPU, eval mode, `trust_remote_code=False`.
- Capture: PyTorch forward hooks on Hugging Face `transformers`. Hook names use TransformerLens-style names (`blocks.{i}.hook_resid_post`) mapped to `gpt_neox.layers[i]`.
- Entry: the model is selected per run from the CLI (`--model`); the fixture model stays the default and the API stays fixture-only, so model execution never runs in an HTTP handler.
- Packaging: `torch`, `transformers` and `safetensors` live in an optional `neural` dependency group; the core install and default test run stay torch-free.
- Token IDs are stored only on content-capture opt-in, because they reconstruct the prompt.
**Alternatives:** Pythia-14m (too weak to be informative), GPT-2 small (heavier on CPU and in tests); TransformerLens (larger dependency tree, and its weight processing changes numerics against the original checkpoint, weakening the non-perturbation check).
**Consequences:** Phase 3 proves the capture pipeline, not semantic interpretability; the model will not answer the cap question reliably and wrong answers are recorded as observed. Replay is teacher-forced and labelled approximate.
**Validation:** the compatibility gate report (`docs/compatibility/pythia-70m-deduped.md`), read-only hooks within 1e-6 of unhooked logits, a golden-logit test, and the Phase 3 exit test.
**Rollback:** remove the `neural` group and `--model`; the fixture path and Phases 1–2 are unaffected. Migration 0003 downgrades cleanly.
