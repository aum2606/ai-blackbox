# ADR-009 — Deterministic fixture model for Phase 1

**Status:** Proposed (Phase 1 plan, decision D1).
**Context:** Phase 1 must show a complete trace of a controlled wrong answer. The failure is injected at retrieval (stale document version). A real tiny model may not answer the numeric question reliably (ADD §8.2 confound policy), and neural access is not needed until Phase 3.
**Decision:** The Phase 1 "model" is a deterministic extractive function, `model_id="fixture-extractive"`, `model_revision` = SHA-256 of its source file, `tokenizer_revision="not_applicable"`. It reads the cap value from the retrieved text. Invocations record `neural_access="unavailable"`, and the API and UI say so.
**Alternatives:** (a) tiny pinned HF model now: unreliable answers, adds torch/transformers and Phase 0 spikes before they are needed; (b) hosted API: violates ADR-008.
**Consequences:** Phase 1 demonstrates trace correlation and provenance, **not** model behaviour or cognition. The model call stays a single function, so Phase 3 adds a real model without changing the run or invocation records.
**Validation:** Stale-document and trace-completeness tests (Phase 1 plan §10); the UI shows "neural access unavailable".
**Rollback:** Replace the function with a real model adapter; schema is unchanged.
